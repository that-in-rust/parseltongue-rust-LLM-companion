# Ideas for the Rust graph from Sikos, *Cybersecurity knowledge graphs* (KAIS 2023, full text) and the MISP threat-sharing platform

*Written 2026-11-05. Sources: Sikos, L.F., "Cybersecurity knowledge graphs", Knowledge and Information Systems 65:3511–3531 (2023), doi:10.1007/s10115-023-01860-3, CC-BY, read in full this time (the earlier H-33…H-41 pass used only the abstract). MISP: misp-project.org features and data-model pages, misp-standard.org core / object-template / galaxy / taxonomy formats, MISP user guide (sharing, sightings, warninglists, feeds, analyst data), and the 323-entry misp-objects relationship vocabulary. Ledger entries H-47…H-59 are the compact form; this note is the reasoning.*

## 1. What the two sources are

**Sikos** surveys graph data models (RDF, labelled property graphs, hypergraphs, multigraphs, named graphs), classifies cybersecurity KGs into four types — Type I: a graph *of the system* (network, flows, attack paths); Type II: threat-intelligence facts; Type III: a vocabulary/ontology; Type IV: several uniquely identified named graphs, one per data source, connected for fusion — and then covers reasoning (rule inference, backward–forward chaining over provenance graphs with alert scores that increase along a path toward a root cause, Bayesian attack graphs for path probability, rule-subsumption to remove redundant rules), ML (anomaly detection taxonomy, MalRank label propagation from a-priori labels + confidence, link prediction for deviation from a learned baseline, GNNs), visualisation ("too much information with too little context"), and fusion (owl:sameAs entity matching).

**MISP** is the de-facto open threat-sharing platform. Its data model: *Event* → *Attributes* (typed atomic facts with `to_ids` = actionable flag, `first_seen`/`last_seen`, distribution level) → *Objects* (templated bundles with `required`/`requiredOneOf` slots) → *Object References* (relationship from a 323-term curated vocabulary). Context layers: *taxonomies* (machine tags `namespace:predicate="value"`), *galaxies* (shared background clusters: threat actors, ATT&CK techniques, tools) attached to events/attributes, *warninglists* (known false-positive lists; `enforceWarninglist` filters them out of exports), *sightings* (confirm / false-positive / expiry on an attribute), *proposals* (ShadowAttribute: suggest a change to someone else's event, owner reviews), *analyst data* (Note / Opinion 0–100 / Relationship, each with its own UUID and creator org, attached *alongside* an element without modifying it, federated through sync), *feeds* (periodically imported external indicator sets), *correlation engine* (exact + fuzzy: ssdeep, CIDR), and *sharing* (distribution levels, sharing groups, push/pull sync with automatic distribution-level decrement).

## 2. The one structural lesson

MISP keeps three things apart that most code-graph tools smear together: **the fact** (attribute/object, owned by its producer), **the context vocabulary** (taxonomy/galaxy, shared and versioned), and **the commentary** (analyst data / sightings / proposals, owned by whoever says it, never edits the fact). Mapped to us: **resolver facts** (exact, owned by the substrate) / **shared vocabularies** (node & edge kinds, role tags, pattern galaxies, background graph of std + top crates) / **annotation layer** (LLM meaning, agent sightings, model-proposed edges, opinions). The annotation layer is where every non-exact thing lives — which makes "exact where the compiler can see, honest where it cannot" (Deep-Insight-01 §8) a storage property rather than a promise.

## 3. Transferable ideas (→ ledger H-47…H-59)

| # | from | idea for the Rust graph |
|---|---|---|
| H-47 | Sikos Type IV | one **named graph per substrate** (rustdoc, rust-analyzer, tree-sitter, student model, git, coverage, LLM-meaning) in one store; every query can include/exclude graphs → "show me the map with the model layer off" is a filter, not a rebuild |
| H-48 | Sikos §4 provenance graphs | **root-cause scoring along paths**: from a failing test / panic site, walk callers; each node's score grows with the number of failing paths through it; rank candidates for the agent (mechanism for H-16) |
| H-49 | MalRank | **risk propagation** over the call graph from a-priori seeds with confidence (`unsafe`, RustSec-affected fn, `panic!`/`unwrap`, untested) → a propagated risk score per pub item; a lens, labelled heuristic |
| H-50 | Bayesian attack graphs | **probabilistic ranking of `MAY_CALL` fan-out** (dyn/generic dispatch): weight each candidate target by evidence (same crate, constructed nearby, only implementor in scope) so the agent sees likely paths first, with the exact set still available |
| H-51 | MISP analyst data | **annotation layer** = Note / Opinion(0–100) / Relationship records with own id + creator (human, agent, model@rev) attached alongside items & edges; never written into the resolver's graph; the home of L6 meaning and model-proposed edges |
| H-52 | MISP sightings + proposals | **agent sightings on proposed edges**: confirm / false-positive / expiry; a model edge becomes "sighted" when an agent actually followed it and it held, or when the resolver later verifies it; confidence evolves instead of being static |
| H-53 | MISP warninglists | **warninglists for code graphs**: community JSON of known-noise items to drop from blast radius / clusters by default (derive-generated impls, `Debug`/`Clone`/`Default`, prelude re-exports, test helpers, `#[cfg(test)]` modules), with an `enforce_warninglist=false` escape hatch |
| H-54 | MISP taxonomies | **machine tags** `namespace:predicate="value"` as the only form for classification: `role:entry-point`, `arch:layer="io"`, `safety:unsafe-boundary`, `hot:true`, `owner:team="net"`; shareable vocabularies, filterable, cheaper than free text |
| H-55 | MISP galaxies | **galaxies = shared pattern clusters** attached to items: builder, typestate, RAII guard, actor/channel, interior mutability, error-enum-with-From, std trait families; the LLM's meaning layer references a cluster instead of re-describing the pattern → compact, consistent, versioned |
| H-56 | MISP `to_ids` | an **`actionable` flag** per record: exact resolver facts are actionable (an agent may edit on them); model/heuristic facts are context-only until sighted/verified |
| H-57 | MISP `first_seen`/`last_seen` | **temporal validity on every edge** from git history of the record stream: `first_seen`/`last_seen` commit → "edges new this week", "stale since", change-frequency per item at near-zero cost |
| H-58 | MISP correlation engine | **automatic fuzzy correlation**: hash the normalised item skeleton (signature shape, trait impl set, error type) and correlate across the workspace and the background graph → "this looks like `tokio::sync::mpsc::Sender`"; also a cheap extra signal for event-2 similarity |
| H-59 | MISP distribution/feeds | **distribution levels + feeds for graph layers**: background graphs of std/top crates distributed as versioned feeds (H-33 as a sync mechanism); workspace graphs `org-only`; annotation records carry their own distribution so meaning notes can be shared without the code |

Rule-subsumption (SRDD) → de-duplicating architecture rules (H-37) is noted but too small for its own entry. owl:sameAs fusion and link prediction are already H-39.
