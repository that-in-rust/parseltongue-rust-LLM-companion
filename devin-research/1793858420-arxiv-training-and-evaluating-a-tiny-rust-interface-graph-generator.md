# Can a sub-100 MB model build a Rust public-interface dependency graph?

**Research decision | 2026-11-05.** Yes to the experiment; no to claiming the result yet. Train a small model to identify *which public contract mentions which exact item, in what role*, and to emit those facts with evidence. Use Rust's toolchain to manufacture and check examples offline. At inference, give the student source and a cheap index of names, not an answer graph or a running compiler. The deliverable is the **graph**, usable without a chat model. A maintainer should be able to ask, in either direction, which public contracts expose a type and inspect why.

The literature supports three distinct bets: a model can learn semantic edges from source; Rust public signatures can support machine-checkable graphs; and specialized code students can be compressed substantially. **None of the papers reviewed establishes their intersection: end-to-end, cross-file Rust public-interface extraction on unseen workspaces below 100 MB peak CPU RAM.** That intersection is a useful research question, not a marketing claim. This refines the [Lossfunk thesis](../docs-lossfunk/02-learned-graph-compiler-thesis.md) and the [public-interface decision register](1793853341-rust-public-interface-dependency-graph-usefulness-form-and-open-decisions.md).

## What the papers actually show

| Primary evidence | Experiment and limit | What we can reuse |
|---|---|---|
| Li, Maddison & Tarlow, [Learning to Extend Program Graphs to Work-in-Progress Code](https://arxiv.org/pdf/2105.14038), sections 3-4, fig. 4 | They supervise a Transformer on ten token-pair relations derived from analyses of Python. In their code-completion corpus the reported F-score exceeded 0.8 for every relation on clean code. Fewer than 0.3% of ordered pairs were connected: predicting nothing could exceed 99% accuracy. Their six-layer, width-512 model uses a quadratic pair layer. The clean edge result is **not** an exact-graph score on broken repositories. | Closest neural precedent. Label buildable source, corrupt it in controlled ways, predict typed edges, and evaluate rare relations separately. Replace dense all-token-pair scoring with sparse span-to-symbol candidates. Don't headline accuracy. |
| Johnson, Larochelle & Tarlow, [Learning Graph Structure With a Finite-State Automaton Layer](https://arxiv.org/abs/2007.04929) | Learns additional relations by walking a supplied graph; reproduces simple static analyses on Python. Learned adjacency that helps a downstream task need not mean what a programmer would call a dependency. | A useful challenger for multi-hop imports: provide module, scope and alias links, then predict a destination. Require an inspectable path and score the named relation itself. Do not turn every learned shortcut into a fact. |
| Jiang, Xu & Zhou, [RULF: Rust Library Fuzzing via API Dependency Graph Traversal](https://arxiv.org/abs/2104.12064); Chen et al., [GRAFT: Generics-Aware Fuzz Target Generation](https://arxiv.org/abs/2608.08637) | RULF traverses a Rust API dependency graph to construct API sequences. GRAFT builds its graph by matching documented types, including generics; the LLM helps synthesize fuzz targets **after** graph construction. GRAFT reports 96.19% compilation success and 80.75% macro-average API coverage on 13 crates. Neither number measures extraction precision or recall. | Closest Rust precedents. Use a compilable downstream program as a witness, without treating one successful program as proof the graph is complete. A return type fitting another function's parameter means “can supply,” not “calls.” The [RAPx API graph](https://safer-rust.github.io/RAPx-Book/5.3-api.html) is a concrete comparator for arguments, returns, generic parameters and type transformations. |
| Eberts & Ulges, [SpERT](https://arxiv.org/abs/1909.07755) | Jointly detects entity spans and classifies relations using one encoder pass and hard negatives. The experiments are on natural-language sentences, not code repositories. | Copy the joint span-and-relation objective, not the vocabulary or the reported scores. A model that can introduce a declaration or reference span missing from Tree-sitter can *generate* graph facts. Pair it with cross-file lookup. |
| Guo et al., [GraphCodeBERT](https://arxiv.org/abs/2009.08366); Le-Cong et al., [AutoPruner](https://arxiv.org/abs/2209.03230) | The first uses data flow in pretraining, including edge prediction and source alignment. The second removes likely false edges from a supplied static call graph. Neither demonstrates discovery of an entire Rust interface graph from files. | Mask edges for an auxiliary training task. Keep a prune-only model as a baseline: it cannot recover an absent node or an edge outside its candidate graph. Report those misses, even if its retained edges are excellent. |
| Shi et al., [Compressing Pre-trained Models of Code into 3 MB](https://arxiv.org/pdf/2208.07120), table 3; d'Aloisio et al., [On the Compression of Language Models for Code](https://arxiv.org/abs/2412.13737) | The first reports a 3 MB student versus 481 MB CodeBERT; accuracies were 59.44 vs 61.82 and 95.43 vs 96.20 on two classification tasks. The latter finds compression tradeoffs differ by task and method. Neither measures our graph accuracy or our process RSS. | Train a cheap recurrent student as a serious control. Quantize *after* establishing uncompressed performance and rerun evaluation by edge type. The result may be that frequent returns survive compression while rare associated types do not. |

**Dataset trap:** [Präzi](https://arxiv.org/abs/2101.09563) and its [archived Rust data](https://zenodo.org/records/4478981) distinguish package dependencies from function calls. They are useful for a separate call-graph experiment, **not** labels for “which type appears in this public signature.” Likewise, two functions mentioning the same type do not establish data flow between them. Keep declared contract, possible composition, and observed call separate.

## One label we actually built and challenged

I built public rustdoc JSON for [`bytes` 1.10.1](https://docs.rs/bytes/1.10.1/bytes/struct.BytesMut.html#method.freeze) locally, with the `std` feature on `aarch64-apple-darwin`, nightly `2026-04-01` (rustc `48cc71ee8`). JSON format **57**, 957 local index records. **That is not 957 public APIs**: the index includes implementation and auxiliary records. Following links, instead of counting records, produced this example:

| Fact in this artifact | What it proves |
|---|---|
| The crate root includes two public `use` records: `BytesMut` targets item 306; `Bytes` targets item 87. | The externally usable paths and the underlying definitions are distinct things. |
| An inherent impl for 306 owns method 900, `freeze`. Its output is a resolved path to 87. | Emit `bytes::BytesMut::freeze --SIGNATURE_USES(return)--> bytes::Bytes`. An inverse lookup on `Bytes` should find `freeze` without storing a second independent assertion. |
| The method's source span starts at line 246 and ends at line 265 of `src/bytes_mut.rs`. | It covers the method, not just the return-type token. Align the occurrence against the actual source before claiming byte-precise evidence. A line move does not create a new item. |
| A separate downstream crate compiled with `fn witness(b: bytes::BytesMut) -> bytes::Bytes { b.freeze() }`. Changing only the declared result to `bytes::BytesMut` failed with `E0308`: expected `BytesMut`, found `Bytes`. | One real positive, one plausible hard negative. This checks external usability, not whole-crate recall. Compilation checks assignability; for cases involving coercions it is not proof of exact declared type identity. Read the declaration too. |

Reproduce on a machine with this nightly, `jq`, and the exact unpacked crate. Set `SRC` to the crate directory. This dependency-free invocation tests this configuration only; use Cargo with recorded flags for general crates. The query prints the method, member-owning impl and local return ID without assuming their numeric values.

```sh
OUT=$(mktemp -d)
rustdoc +nightly-2026-04-01 --edition 2018 --crate-name bytes --crate-type lib \
  --cfg 'feature="std"' -Z unstable-options --output-format json -o "$OUT" "$SRC/src/lib.rs"
jq '. as $d | .index[] | select(.name == "freeze") as $m |
  $d.index[] | select((.inner.impl.items? // []) | index($m.id)) |
  {method: $m.name, owner: .inner.impl.for.resolved_path,
   result: $m.inner.function.sig.output.resolved_path, span: $m.span}' "$OUT/bytes.json"
rustc +nightly-2026-04-01 --edition 2018 --crate-name bytes --crate-type rlib \
  --cfg 'feature="std"' -o "$OUT/libbytes.rlib" "$SRC/src/lib.rs"
printf '%s\n' 'pub fn witness(b: bytes::BytesMut) -> bytes::Bytes { b.freeze() }' |
  rustc +nightly-2026-04-01 --edition 2018 --crate-type lib --emit metadata \
    --extern bytes="$OUT/libbytes.rlib" -o "$OUT/client.rmeta" -
```

## Training data: design the answer key before training the student

1. **Freeze the unit of truth.** One example belongs to a repository revision, Cargo package, target triple, enabled features, and toolchain. Start with three relations: `public_path --EXPORTS--> definition`; `contract --SIGNATURE_USES(role)--> type_or_trait`; `type --IMPLEMENTS--> trait` qualified by impl generics and bounds. For signatures preserve parameter index, return, public field or bound, and nested type position: `Result<Vec<T>, E>` must not flatten into four interchangeable names. Keep reference/borrow and alias spelling as evidence. External definitions may be endpoints, but do not invent local bodies for them. Exclude private nested functions, body calls, and inferred runtime data flow from this score.
2. **Extract reachable contracts, not tokens spelled `pub`.** Walk root modules, public paths, re-exports, inherent and trait impls; keep a visited set for cycles and multiple paths to one definition. A public item in a private module may be exposed under an alias; `pub(crate)` is not an externally usable path. Handle trait items with inherited visibility. Separate explicit from blanket/synthetic impls and report unsupported cases as such. An inaccessible type in an otherwise visible signature can be recorded as an opaque endpoint, not advertised as an importable path. See the [Rust visibility rules](https://doc.rust-lang.org/reference/visibility-and-privacy.html).
3. **Use mechanical labels first.** Pair exact crate sources with [docs.rs rustdoc JSON](https://docs.rs/about/rustdoc-json) when the build recipe is known; otherwise rebuild using pinned nightly Cargo/rustdoc. Record artifact digest and `format_version`; downloads can be absent and schemas change. Join [opaque rustdoc IDs](https://docs.rs/rustdoc-types/latest/rustdoc_types/struct.Id.html) within one artifact only. Normalize to a package-qualified definition key + namespace + owner/impl discriminator; track public paths separately. Compare exports with [cargo-public-api](https://github.com/cargo-public-api/cargo-public-api); useful for catching our adapter's bugs, but not an independent oracle because it also reads rustdoc. Expand the external compile-witness suite and audit disagreements against source.
4. **Separate missing proof from a negative example.** Store input file digest and byte spans, normalized endpoints, role, configuration, label origin, and one of `verified / contradicted / unresolved`. Preserve the expansion or import chain when available. Sample hard negatives: two crates' `Error` types, an inaccessible alias, swapped argument and return, an impl available only under another feature. Mere absence from rustdoc is not a negative, especially for hidden docs, incomplete builds or unavailable expansions. Treat body-only edits and ordinary comment insertions as positive invariance pairs; feature changes and a renamed re-export are meaningful counterexamples.
5. **Keep the Lossfunk teacher, change its authority.** A strong LLM can propose a missed fact, suggest a source witness, generate adversarial near misses, or label an incomplete snapshot. Store its output and version separately. Promote a claim only after independent checking or explicit human adjudication. Never grade the student solely against its teacher. Train on both natural incomplete commits and seeded breakages: if the only file that disambiguated two targets is removed, the correct answer may now be “unresolved,” not the old target.
6. **Split by repository family before extracting windows.** Use the proposed 50 pinned OSS Rust libraries as training families; reserve *additional*, disjoint families for validation, confidence calibration and a sealed test. Represent async, networking, storage, compilers and embedded/no-std code; reserve some large workspaces, not just standalone crates. Deduplicate forks, versions, vendored dependencies and generated templates across splits. Keep each clean/corrupt pair together. Publish source manifests, licensing/provenance, feature matrices, split hashes, label builder and replayable fixtures; do not redistribute source or teacher output without the applicable rights. A public model's pretraining exposure may be unknown: add newly authored blinded fixtures and report that limitation.

## What to fit in memory

| Candidate, in order of experiment | Why train it | Memory and failure mode |
|---|---|---|
| **Sparse span-pointer student** (preferred): four encoder blocks, width 256, feed-forward width 1,024, 8,192 case-sensitive subword IDs. | Predict declaration spans and reference spans from Rust source; for each reference predict a role and point to a retrieved declaration, or abstain. It can add nodes and edges absent from the parser. Train jointly on spans, relation labels and target identity; oversample difficult configurations. Distill from verified teacher distributions only where available. | About 2.10M embedding + 3.15M block weights, before heads/positions: roughly 5.25 MB int8 or 21 MB fp32 **for those weights only**. Bound windows (start with 512 tokens) and score at most 32 candidate definitions per reference. A missing target in the lookup set is an end-to-end miss, not a classification success. This is a proposed shape, not a pretrained checkpoint. |
| **Post-train an existing code model:** [Salesforce CodeT5-small weights](https://huggingface.co/Salesforce/codet5-small), [paper](https://arxiv.org/pdf/2109.00859). | This is the literal open-weight post-training track. Teach it a small action language: declare a source span, expose a path, link two numbered candidates with a role, or abstain. Require grounded pointers; never accept a well-spelled but nonexistent identifier. | 60M parameters imply a theoretical 30 MB at four bits each, before scales, unquantized layers, tokenizer, runtime and encoder/decoder state. Measure CPU peak RSS early. Quantized autoregressive decoding may cost more than the pointer model for no advantage on exact links. |
| **BiLSTM and no-neural controls.** Train a small contextual recurrent model with the same pointer head; also run lexical scope/import rules without it. | Tests whether a Transformer contributes anything once aliases and scope are available. A prune-only student measures the separate value of rejecting bad links. | Compare at the same candidate and evidence budgets. If rules or a recurrent student win at equal coverage, publish that result and ship the better generator. |

At inference, stream source windows and candidate records from an on-disk name index. First pass proposes declarations; second pass resolves references across files. The host checks endpoints, spans and schema, merges aliases, records uncertainty, and serves forward/reverse traversal. An endpoint validity check does **not** prove semantic correctness. Keep raw model, validator-only and accepted graph measurements separate. No compiler, GPU or API teacher hidden inside the measured CPU inference path. The graph can outgrow RAM; stream it to disk instead of retaining the repository in the inference worker.

## What would convince a skeptical maintainer?

| Test | How to score it without fooling ourselves |
|---|---|
| **Whole graph on unseen workspaces** | Freeze the current Parseltongue Tree-sitter extractor and its mapping to the declared schema; report unsupported kinds explicitly. Compare against simple scope/re-export rules, a prune-only model, and the proposed end-to-end generator. Also compare with a build-aware rustdoc baseline on clean code and [rust-analyzer](https://rust-analyzer.github.io/book/contributing/architecture.html) on partial code, reporting inputs, cost and unsupported relations separately. Never hand compiler candidate IDs or gold endpoints to the student at test time. |
| **Right item, role, direction and configuration** | Exact-match a normalized edge tuple, not the spelling of a name. Report node recall, public-path recall, per-relation precision/recall/F1, micro totals and macro by workspace; publish raw TP/FP/FN and support. Score the final graph over *all* gold facts; also report candidate recall@32 and conditional linker accuracy to locate misses. Keep separately sampled adjudication of model-only facts and suspected omissions so a defective label builder cannot cap apparent recall. |
| **Useful uncertainty** | On paired clean, partially edited, cfg-switched and unbuildable inputs, plot precision versus fraction of sites resolved. Count false confident links, correct abstentions on genuinely ambiguous sites, and recoverable facts lost. Slice re-exports through private modules, generic/associated types, macro-generated items, name collisions, external crates and cross-file links. Bootstrap differences by workspace, not by individual edges. |
| **Useful answers for systems programmers** | Blind a reviewer to extractor identity. Ask “which exported contracts return this type?” and the reverse “which foreign types does this public trait expose?” Grade returned item sets against hand-checked answers, inspect both endpoint witnesses, and measure evidence tokens per correct answer. Do not conflate a smaller graph with a more accurate one; the project's 5% token-size aspiration is a separate measurement. |
| **Actual sub-100 MB deployment** | Hard gate: CPU inference worker peak RSS **<100,000,000 bytes**, not model download size, batch 1, fixed thread count, cold launch and warmed full-repo sweep at maximum declared window and candidate count. Include runtime, tokenizer, resident mapped weights, activations and candidate buffers. Report OS/CPU, quantization, p95 per-file latency, files/s and peak bytes. Measure integrated CLI/daemon plus index/graph writer separately; if the whole tool is advertised as sub-100 MB, it must pass too. On macOS use maximum resident set from `/usr/bin/time -l` (bytes); on Linux GNU time `-v` reports KiB. Training and offline labeling are separate budgets. |

**First decision gate (proposed, not a result):** build the label adapter and a small, audited cross-crate benchmark *before* spending on the 50-library teacher run. Train the recurrent control and the pointer student, then the existing-checkpoint challenger. Set deployment thresholds on validation only. On the sealed test, require a positive lower bound on the paired 95% workspace-bootstrap difference in macro edge F1 over the strongest source-only non-neural baseline, at matched resolution coverage, with no increase in the rate of confidently wrong links. Publish clean and incomplete strata separately. If there are too few workspaces for an informative interval, call the pilot inconclusive. If only partial-code recovery improves, describe exactly that narrower win. If none improve under the RSS gate, retain the deterministic graph and publish the benchmark rather than shipping unearned confidence.

**Evidence boundary:** the paper results above are the authors' measurements. The `bytes` positive and negative compiler checks were run for this note. No student was trained, no model RSS was measured, and no whole-workspace graph score is claimed here.
