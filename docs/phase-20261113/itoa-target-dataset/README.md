# itoa target dataset — the expected full item graph

## The answer

**This folder holds the expected full item dependency graph of pinned itoa 1.0.18: 73 nodes,
368 edges, 33 impl blocks and 10 unresolved or inactive sites. It is an unreviewed draft, so
nothing may be accepted against it yet.**

- Written by Devin from reading the pinned source. Every cited line is checked against the
  pinned bytes, but no row has been reviewed and nothing is frozen.
- Never a production input. The mapper must not read it.
- Rows are named by symbolic label (`Buffer::new`), not by production identity.
- It does not cover the whole source: operators, types inside bodies, literals and repeated
  same-line sites are missing.

## What is settled and what is not

```text
           total   no open blocker   blocked
nodes         73                26        47
edges        368                29       339
```

A row is blocked when it rests on something undecided or unchecked. Counts below are rows,
nodes and edges together, and one row can carry several reasons:

```text
324  generated by a macro: which file and owner the item belongs to is undecided (OD-2);
     279 edges and 45 nodes
119  target is outside itoa (core): its identity is not verified
 85  source range of the site is not verified
 56  dependency of a non-function item: the rule is undecided (OD-8)
 29  source item identity is not verified
 12  call that depends on inference over core types
  8  visibility of an external trait is not verified
  2  file-module ownership is undecided (OD-7)
```

Edges by kind: 102 `calls`, 98 `uses_type`, 70 `contains`, 62 `reads`, 32 `implements`,
4 `imports`, 0 `reexports`, 0 `derives`. Edges by target: 194 itoa items, 119 external,
55 builtin.

## Regenerate and test

From the repository root, with the pinned itoa checkout available:

```sh
python3 docs/phase-20261113/itoa-target-dataset/itoa-expected-graph-builder.py \
  --pin-file docs/phase-20261111/phase-one-benchmark-pin.json \
  --source-root /path/to/rust-tools/itoa \
  --output-directory docs/phase-20261113/itoa-target-dataset
python3 -m unittest discover -s docs/phase-20261113/itoa-target-dataset -p 'test_*.py' -v
```

The builder fails if the checkout is not at the pinned commit or a cited line does not match.
Two runs write identical bytes.

## What it takes to freeze it

1. Decide OD-2, OD-7 and OD-8 ([backlog](../BACKLOG-deferred-work-open-decisions.md)).
2. Review every row against the source and add the constructs not covered.
3. Map symbolic labels to production identities.
4. Record the digest of the frozen files in the SOP run
   ([SOP S1](../SOP-itoa-full-item-graph-acceptance.md)).
